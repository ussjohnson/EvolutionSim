# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Plain `javac`/`java` project — no build tool, no external dependencies. Sources live under `src/evosim/` in subpackages, so the compile command must gather them recursively:

```sh
# Compile everything into bin/ (Git Bash / POSIX)
javac -d bin $(find src -name '*.java')

# PowerShell equivalent
javac -d bin $(Get-ChildItem -Recurse src -Filter *.java | ForEach-Object FullName)

# Launch the GUI (default): settings screen → live sim → results
java -cp bin evosim.Main

# Run headless (dev/test harness); --report also writes an HTML report
# optional: --seasons (yearly climate cycle), --wraparound (toroidal edges)
java -cp bin evosim.Main --headless --seed 42 --ticks 500 --width 40 --height 30 --pop 150
java -cp bin evosim.Main --headless --seasons --seed 42 --ticks 1500
java -cp bin evosim.Main --report out.html --seed 42 --ticks 500

# Run the smoke/regression test (determinism + survival band)
java -cp bin evosim.SmokeTest
```

## Architecture

An evolution "terrarium": animals defined by a genome of evolvable traits live on a 2D tile grid, eat (plants and/or each other), and reproduce asexually with mutation. Genomes that drift far enough apart are tracked as distinct species. All four build phases are complete (see `.claude/plans/keen-riding-hare.md`): core model, headless engine, Swing GUI (settings → live map → results), and the stats/HTML report.

Packages under `src/evosim/`:

- **`model`** — the domain, with no engine/UI dependencies:
  - `GeneType` (enum) is the catalog of the 17 hereditary genes; its declaration order defines the canonical genome vector. Each constant carries bounds, mutation variation, and a metabolic-cost weight. **Add a gene by adding a constant here.**
  - `Gene` is one evolvable trait (value + bounds + variation); `Genome` is a `Gene[]` indexed by `GeneType.ordinal()` and provides `norm()`, `mutatedCopy(rng)`, and the `distance()` metric used by both speciation and kin perception.
  - `Animal` holds a `Genome` plus per-individual state (position, energy, mass, hp). Its *derived* attributes (metabolism, growth, reserves, effective stealth, aging pace) are computed from genes, not inherited — each encodes a tradeoff. Animals have no colour of their own — they render in their species' colour (see `Species`/`Coloring` below); SIZE sizes the on-screen icon instead. `agingDeathChance(tick)` is a Gompertz hazard (risk rises exponentially with age, evaluated at the animal's own `agingPace()` — faster metabolism speeds up the clock, SIZE slows it via the same discount that already applies to raw upkeep) rolled once per tick in `Behavior.upkeep`; deliberately *not* a hard lifespan cap, and deliberately not its own gene — a longer life is always bought with costs the sim already charges elsewhere (metabolism, growth time, stealth), never a free perk. `regen()` (also called from `Behavior.upkeep`) slowly heals HP each tick out of spare energy (`Balance.HP_REGEN_RATE`/`HP_REGEN_ENERGY_COST`) — never free, since it competes with growth/reproduction for the same energy pool.
  - `Tile` is a grid cell with foliage/fertility, a fixed `BiomeType`, and the raw normalized temperature/moisture it was generated from; over-grazing degrades fertility (the environment-overuse mechanic). It also holds a `carrion` pool: an animal that dies of anything but predation leaves its body here (`addCarrion`), a decaying store of meat energy that meat-eaters can `scavenge` and that slowly returns to the soil as fertility as it rots (`recover`, `Balance.CARRION_*`) — closing the "where does dead biomass go" loop and recycling nutrients. `recover(rng, seasonGrowthFactor)` takes a global seasonal growth multiplier (see `World` seasons below). `BiomeType` (tundra/desert/grassland/forest/rainforest) is the spatial niche differentiation the balance notes called for: each biome scales the tile's fertility and foliage-regrowth rate, and imposes a "climate stress" fraction on top of every resident animal's metabolism (see `Animal.metabolism(double)`, applied in `Behavior.upkeep`) — so different regions favor different survival strategies instead of one lineage dominating everywhere uniformly. Each `BiomeType` constant owns an "ideal" point in (temperature, moisture) space rather than being carved out by a hand-coded threshold tree; `BiomeType.classify` assigns a tile to whichever biome's ideal point is nearest (a Voronoi partition), so **adding a biome later is just adding a constant** — no classification logic to touch, no risk of breaking existing boundaries. SIZE discounts specifically the climate-stress portion (`Balance.SIZE_CLIMATE_PROTECTION`, Bergmann's rule: bigger bodies retain heat better), the same "gene buys a discount on one upkeep cost" pattern already used for raw metabolism (`SIZE_METABOLIC_DISCOUNT`) and aging pace (`AGING_SIZE_PROTECTION`) — so cold-hardiness is a real, SIZE-gated tradeoff (bought with SIZE's usual costs elsewhere) rather than every animal being equally punished by harsh biomes. Camouflage is biome-specific too: `GeneType.CAMO_TEMP`/`CAMO_MOISTURE` are the climate an animal is adapted to blend into, and `Animal.effectiveStealth(double, double)` scales the STEALTH-derived bonus down by the mismatch between those genes and the tile's actual temperature/moisture (`Balance.CAMO_MISMATCH_K`) — so stealth specialized for one biome's cover doesn't fully transfer to a climatically different one.
  - `Species` + `SpeciesRegistry` do online centroid clustering: each birth joins the nearest species within `Balance.SPECIATION_THRESHOLD` or founds a new one and records its parent species (same species is never a threat, prey, or mate — see `Behavior` below). A species' centroid is a bounded moving average (`Balance.CENTROID_HORIZON`), not a lifetime mean, so it keeps tracking drift instead of freezing once well-established; **species descriptions/genome dumps everywhere (results table, taxonomy tree, HTML report) read the live `centroid()`, never the frozen `founder()`**, so a lineage that drifts (e.g. toward herbivory) shows that drift immediately instead of the label going stale. `NameGenerator` builds a name from 2-4 genome-derived syllables (count and shape both vary with the genome, not a fixed CVCVCVCV pattern) so names vary in length/rhythm while staying a pure function of the same normalized vector the distance metric uses (similar genomes still get similar-looking names). `SpeciesLineage` turns the flat, parent-id-linked species list into a tree (roots/children/depth-first order, plus a shared `leftPad` helper for aligning population history to the sample-tick axis) for the family-tree chart and taxonomy views. A species' display colour is assigned once at founding (`SpeciesRegistry`, via package-private `Coloring`) by lineage, not by genome: a root species (no in-sim ancestor) gets a hue spread from every other root via the golden angle for maximal separation, while a child species inherits its parent's hue plus a small random nudge (`Balance.SPECIES_HUE_JITTER`) — so a family of related species reads as a visible colour gradient in the map/taxonomy tree, and every individual animal renders in its *species'* colour rather than its own (mutating) genome, so a species reads as one consistent colour even as members drift.
  - `Balance` holds every tunable constant (mutable statics) — the one place to adjust ecosystem balance.
- **`engine`** — depends on `model`:
  - `RandomSource` is the single seeded RNG threaded everywhere; **no `Math.random()` in a run**, so a seed reproduces exactly.
  - `World` owns the tile grid, the animal list, the registry, and the deterministic `tick()` loop. **Seasons:** an optional global yearly climate cycle (`seasonalPhase`/`seasonalGrowthFactor`/`seasonalColdStress`, a pure sine function of the tick, off on the headless/dev `create` path and on by default via `fromSettings`) that swings foliage regrowth up in summer and layers extra climate-stress upkeep on everything in winter — a dynamic environment rather than a static one, still fully deterministic. **Interactive god-tools:** UI-thread edits are enqueued (`enqueue`) and drained on the engine thread at the top of `tick()` (so all model mutation stays single-threaded and the seeded test path, which never enqueues, stays deterministic); see `Interactions`. **Wildfire** (`ignite`/`spreadFire`) is user-triggered fire that spreads to adjacent foliage each tick, strips it, and kills residents. **Death is centralized** in `animalDied(a, cause, leaveCarrion)` (removes from grid, tallies the species, deposits carrion unless the victim was eaten, bumps the death-flow counter) so carrion and the birth/death flow counters stay consistent; `spawnAnimal`/`killAt` back the spawn/smite tools. Population-aggregate helpers (`meanGenome`, `meanMass`, `dietCounts`, `biomeCounts`) feed the time-series stats. One animal per tile (`Tile.resident` is the occupancy index; `Animal` x/y is the source of truth). Optional toroidal wraparound (off by default, per-run via `SimSettings.wraparound`) is centralized in `World.canReach`/`wrapX`/`wrapY`/`wrappedDeltaX`/`wrappedDeltaY` — every place that turns an offset into a tile coordinate (`Perception`'s scan window, `Behavior`'s adjacency/movement) must go through these rather than raw arithmetic or `inBounds`, or it'll silently stop working at the map edge under wraparound. The `World` constructor generates biomes before placing tiles: `NoiseField` (package-private) is hand-rolled smooth value noise — a coarse random lattice bilinearly interpolated with smoothstep easing — sampled twice per axis (coarse + fine octave, blended) to produce temperature and moisture fields, which `BiomeType.classify` turns into contiguous, organic biome regions (`Balance.BIOME_NOISE_SCALE` controls region size). The blended octaves have a central tendency (rarely reach the true 0/1 extremes), so raw samples are contrast-stretched to fill `[0,1]` per world before classification — otherwise biomes whose ideal point sits near an extreme would barely appear; this keeps `BiomeType`'s anchor points meaningful regardless of how the noise scale/blend is tuned later, rather than requiring anchors to be hand-fit to one specific noise shape. Draws from the same seeded `RandomSource`, so it stays fully deterministic.
  - `Perception` scans the awareness-radius window (bounded, not O(n²)); `Behavior` is the per-animal decide/act logic (threat response → scavenge carrion underfoot → hunt → graze → reproduce → seek a better-matching biome → wander → rest, then upkeep). Meat-eaters (`DIET >= Balance.SCAVENGE_MIN_DIET`) prefer a safe carrion meal on their own tile over a risky chase; upkeep's climate stress is the tile biome's plus any seasonal winter cold.
  - `Interactions` holds the god-tool command factories (`rain`/`drought`/`spawn`/`smite`/`fire`/`meteor`/`bloom`), each a `Consumer<World>` the UI enqueues; randomness (spawned genomes, fire spread) is drawn from the world's own seeded RNG on the engine thread so nothing crosses the UI/engine boundary. Same-species animals are never treated as a threat or prey — a hard boundary against cannibalism, on top of the fuzzy genetic kin-distance check that only protects close relatives *within* a species. Predators eating other predators ("intra-guild predation") transfer much less usable energy than eating an herbivore, scaled by the victim's own DIET (`Balance.CARNIVORE_MEAT_PENALTY`): this closes a real energy-conservation loophole — `MEAT_ENERGY` per unit mass vastly exceeds `GROWTH_ENERGY` per unit mass invested, so without the penalty a closed loop of carnivores killing each other could manufacture net energy from nothing and sustain a population with no herbivores or plants anywhere in the food chain. The biome-seeking priority reuses `CAMO_TEMP`/`CAMO_MOISTURE` (an animal's adapted climate, otherwise used for stealth) as habitat preference too: an animal idling somewhere climatically poor (`Balance.BIOME_SEEK_MISMATCH_TH`) takes a step toward whichever empty adjacent tile matches its climate better, then settles once it's good enough — no separate gene needed. Every `attack()` call is recorded on `World` for the tick (cleared at the start of the next `tick()`) and surfaced via `Snapshot.Fight` so the map can draw a fight indicator. Movement direction (`moveToward`/`moveAway`) and distance (`cheb`) use `World.wrappedDeltaX/Y` so an animal takes the short way around the edge when wraparound is on, not always the raw-coordinate direction.
  - `SimulationEngine` runs `tick()` on a daemon thread with play/pause/stop + a ticks-per-second throttle, publishing an immutable `Snapshot` per frame via `AtomicReference` for the UI (the snapshot also carries per-tile carrion + fire arrays and the current season, for rendering). `StatsCollector` owns the sample-tick axis and the whole-ecosystem time series: global population, average fertility, **the population-mean of every gene** (the evolution signal, `geneMean`), mean body mass, per-guild diet counts, per-biome occupancy, and per-interval births/deaths (`World.take*SinceSample`). Per-species history still lives on `Species`.
- **`config`** — `SimSettings` (world params + per-gene start ranges + `wraparound` toggle + `founderSpeciesCount` + `seasonsEnabled`/`seasonLength`, consumed by `World.fromSettings`). When `founderSpeciesCount` > 1, `World.seedPopulation` draws that many cluster centers uniformly from each gene's *full* range (independently-random genomes sit ~0.41 apart on average, comfortably past `SPECIATION_THRESHOLD`) with a normal `FOUNDER_GENE_BAND`-width band around each — so a run can start already speciated instead of waiting on in-run drift.
- **`ui`** — Swing, EDT-only. `MainWindow` (CardLayout: settings → sim → results). `SimView`'s live screen adds a **god-tools palette** (Inspect / Rain / Drought / Spawn / Smite / Wildfire / Meteor brushes with a brush-size slider, plus a global Bloom event) that paint onto the map via `MapPanel.onTilePointer` and enqueue `Interactions` commands, a **Trends** tab (`LiveChartsPanel`: live population line + births/deaths + diet mix, fed a defensively-copied stats frame each UI frame), and a season indicator in the status bar; `MapPanel` also renders carrion marks, a flickering wildfire overlay, and a brush cursor. The **Results** screen adds a **Trait Evolution** tab (`TraitChartPanel`: every gene's population-mean over the run with a checkbox selector, on a shared `MultiLineChart`) and an **Ecology** tab (`EcologyPanel`: population, diet-guild and biome composition via `StackedAreaChart`, fertility, birth/death pulse, and a cause-of-death bar chart). `MultiLineChart`/`StackedAreaChart` are dependency-free Swing chart primitives, the on-screen twins of the SVG charts in the report. `SettingsPanel` builds a `SimSettings` (starting population is drawn from a narrow per-gene band by default — see `Balance.FOUNDER_GENE_BAND` — not the gene's full range, so speciation is something that emerges during a run rather than being pre-baked into 150 unrelated founders; a "Starting species" spinner sets `founderSpeciesCount`); `SimView` renders the live run (`MapPanel` + `StatsSidebar` + `InspectorPanel`) polling the engine snapshot via a ~30fps `Timer`. Clicking a tile in `MapPanel` selects it (highlighted, tracked by tile coordinates not animal id) and `InspectorPanel` shows its biome, foliage, and (if occupied) the resident animal's species/vitals/full genome, re-read from the snapshot every frame — this is why `Snapshot` carries a per-tile biome array alongside foliage, `Snapshot.Dot` carries per-animal id/species/vitals/genome/effective-stealth, and `Snapshot.Fight` carries this tick's attacker/target pairs. `MapPanel` tints each tile by its `BiomeType`, shaded darker toward bare ground and toward full tint at lush foliage. Each animal renders in its species' colour (identity, not individual trait), shaped by DIET (circle/diamond/triangle for herbivore/omnivore/carnivore) with a DIET-coloured outline (green through red) as a second, redundant reading of diet, sized by mass, faded toward transparent by its effective stealth on its current tile — capped at 50% opacity (`MapPanel.MIN_OPACITY`) — and connected by a red line + "clash" spark to anything it attacked this tick. `MapPanel` renders tiles at a fixed pixel size scaled by a zoom factor (not "fit to container"), sits inside a `JScrollPane` for panning once zoomed in, and is zoomed via the control bar's slider or the mouse wheel (kept in sync through `MapPanel.onZoomChanged`). `ResultsPanel` shows the end-of-run summary — a `LineageTreePanel` branching family-tree diagram (each species a horizontal ribbon on its own `SpeciesLineage.dfsOrder` row from birth tick to extinction/current tick, thickness tracking population, with a vertical connector back to its parent's row at its birth tick, and a hover tooltip for full species info; no line-count cap, wrapped in a `JScrollPane` so species founded late in a long run are never silently dropped) plus tabs for a `SpeciesTreePanel` (taxonomy `JTree`) and a sortable/filterable species `JTable` (click a row for a full detail panel below) — with a "Save HTML report" button.
- **`report`** — `SvgChart` (hand-rolled SVG line charts and the `lineageTree` branching family-tree diagram — the SVG mirror of `LineageTreePanel`, using `<title>` elements for native in-browser hover tooltips) and `HtmlReportWriter` (self-contained HTML: summary, family-tree diagram, population, trait-evolution and diet-guild charts, average-fertility chart, a mortality breakdown, taxonomy outline, species field guide, superlatives). Shared by the GUI Save button and the `--report` flag.

### Invariants to preserve
- **Determinism:** all randomness flows through `World.rng()`; iteration is id-ordered before any seeded shuffle. Don't introduce `Math.random()`, `HashMap` iteration over model objects in the tick path, or wall-clock/threading-dependent behavior in the engine.
- **Layering:** `model` must not import `engine`/`ui`. `Balance` lives in `model` because both layers read it.
